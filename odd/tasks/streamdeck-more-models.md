# Support Stream Deck Classic, XL, Mini and Neo

Large feature on branch feat/more-models (from main @ 41b3688). Promote the four registry entries marked `Support::Planned` to full support like the Stream Deck +. No hardware is available: everything is verified with simulated devices, and the docs must say so.

## Specs
S1. "vamos a hacer la modificacion para incorporar mas modelos del stream deck" Contract: discovery recognizes Stream Deck Classic/MK.2 (PIDs 0x006D 0x0080 0x00A5 0x00B9, 15 keys), Stream Deck XL (0x006C 0x008F 0x00BA, 32 keys), Stream Deck Mini (0x0063 0x0090 0x00B3 0x00B8, 6 keys) and Stream Deck Neo (0x009A, 8 keys + 2 touch buttons + info window). PID 0x0060 (original Classic, its own protocol) stays out of scope. Every model gets its own data root (devices/<id>/) and works alongside the others (multi-device). Stream Deck + and + XL behave byte for byte as today.
S2. Human choice "Completo, como el +": per model, detection, key images, actions, profiles/folders/pages, editor and a hardware preview of that model in the UI; status texts and messages name the model; controls a model lacks (dials, strip) are hidden, not broken.
S3. Human choice "No, solo simulado": each model's protocol path is verified with a simulated HID device (input reports decoded, output reports captured and checked for size, format, rotation and chunk headers, brightness/sleep/blank reports); the docs say it was implemented from Elgato's HID documentation and validated with a simulator, with hardware validation pending.
S4. Neo touch buttons, human choice "Asignables con acciones propias (recomendado)": the 2 touch buttons are bindable controls with their own actions (new trigger in layers.conf; readers that do not know it keep the line, never drop it), shown in the editor and the preview; no image upload (Elgato documents none).
S5. Neo info window, human choice "Info por página, como zona del strip (recomendado)": the 248x58 window shows per-page content like a + touch strip zone (image/text and live info such as clock, timers, now playing), without touch.
S6. Classic background, human choice "Sí, incluirlo": the Classic (MK.2 family) background image covering the 15 keys (480x272 LCD background command) can be set from the app; the HID command is implemented from Elgato's documentation and verified only by simulation.
S7. Mini: the legacy Mini protocol (BMP key images, its own input layout, image header and feature reports for brightness/logo/sleep) is implemented; the refusal of the Mini is removed.
S8. Docs and packaging: udev rule and installer cover every supported PID; README, site (index/docs), DESIGN.md, DEVICES.md, CHANGELOG and screenshots describe the six models honestly (simulated only for the new four). "en las documentaciones agrega apartados exclusivos para cada modelo, y las preview para cada modelo" Contract: the docs site (docs/docs.html devices section, and the landing page's device summary linking to it) has one dedicated section per model (+, + XL, Classic, XL, Mini, Neo) with its controls, sizes, product ids, validation status (hardware or simulator only) and that model's generated preview screenshot (docs/screenshots/preview-<id>.png, produced by the documentation screenshot test for every supported model).

# Several Stream Decks at once, with a 'Current' selector

Large feature on a branch stacked over feat/stream-deck-plus-xl (PR #5, not merged). Human decisions: two connected devices work live at the same time; the selector only appears with several connected models and its caption says 'Current'.

## Specs
S1. “eso deberia aparecer solamente cuando tengo mas de un stream deck conectado y dejarme seleccionar el stream deck para configuraro.” Contract: the header selector is hidden unless 2 or more DISTINCT models are connected; its entries are the connected models; choosing one makes the window show and edit that model's configuration; with no device connected there is no selector (the window shows the last used model); the old 'Preview as' behavior (previewing a model with no device) is removed.
S2. “La leyenda de preview esta de mas, solo deberia decir 'Actual'.” Human choice: the caption is 'Current' (English UI): no 'Preview as'.
S3. (human choice 'Los dos funcionan a la vez') Contract: every connected device runs its own configuration live (artwork and input actions) at the same time; the selector only chooses what the window edits. Unplugging one leaves the other running.
S4. (parent decisions) Profiles stay per MODEL: two devices of the same model mirror each other completely (same session: artwork, active page, timers; a key on either runs the same action; brightness/sleep per model). Selector entries are plain model names. Startup/selection: show the last used model if connected, else the first connected (sorted by HID path); when the shown model's last device is unplugged show the remaining one; with none left keep the current one; device.json stores the last shown model (written after a successful switch, never when opening fails). Header status lists the connected devices ('Stream Deck + and Stream Deck + XL connected', '... x2' for duplicates). OBS menu and Test action act on the shown session only. Focus-based profile switching reaches every session.
S5. Verification without hardware: a real-pipeline test with the real HID hub over two simulated devices (+ and + XL) into the window (the kind of test that found the key-hold bug): keys/dials/touch on each device run that model's actions, each device receives only its own model's images, unplug one keeps the other alive, two simulated + devices mirror, shutdown blanks both, no store crosses roots.
S6. Docs: README, site, docs, DESIGN, DEVICES, CHANGELOG and the screenshots describe the new selector (the 'Preview as' text goes away) and multiple devices; the validation status of the XL stays honest (simulated only).

## Architecture (from the exploration)
- HID hub (lib): one hub thread enumerates every supported model (sorted by HID path, DeviceKey{path, serial, model}), one session worker per device (extracted per-connection loop), never opens a live path twice, events tagged with the device and model, artwork/controls addressed to a MODEL and fanned out to every device of it with the last snapshot cached and replayed on attach, per-device shutdown blanking.
- Sessions (bin): one complete session per model kept alive (own widget tree built once, own FeatureRuntime, layer worker, info worker, per-session MonitorEvent channel); the window = shared header + GtkStack of session bodies; app-scoped: tray, update controller, focus observer, device lifecycle. Reuse open_session. The T3b data-swap switching is replaced by selecting a stack child.

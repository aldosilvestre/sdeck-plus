# Stream Deck + XL support with automatic detection

Large feature, five sequential work units. Decisions confirmed by the human: PER-MODEL SEPARATE data; with no device connected the app shows the last used model plus a 'Preview as' selector; the app detects the connected model automatically and adapts dynamically; the user has no XL+ hardware so everything is verified by simulation; the docs must state XL compatibility.

## Specs
S1. “la aplicacion debe comportarse dinamicamente dependiendo si conecto una stream deck + o una stream deck + XL y detectarla automaticamente.” Contract: discovery matches PID 0x0084 (Stream Deck +) and PID 0x00C6 (Stream Deck + XL), reports the model with the connection state, and the whole app (stores, workers, editor, preview, rendering, strings) follows it, including when the user unplugs one model and plugs the other while the app runs; one device at a time (first match).
S2. “a la hora de configurar la preview debe ser del stream deck + XL.” Contract: with an XL+ connected (or selected with 'Preview as' when nothing is connected) the preview, control pickers, catalog/preset guards, accessible names and keyboard navigation describe the XL+: 36 keys (9 columns x 4 rows, row-major numbering), 6 dials, one 1200x100 touch strip with 6 touch sections of 200 px aligned with the dials. The Stream Deck + preview and behavior stay exactly as today.
S3. “lo otro lo puedes simular” Contract: the XL+ protocol path is verified with a simulated HID device that emits 0x01 input reports (36 keys, 6 encoders, touch with the XL tap length 0x10) and captures 0x02 output reports (key images 0x07, window images 0x0B/0x0C) asserting size, rotation and chunk headers; the UI model switch is verified through injected discovery; no real device is needed.
S4. “la documentacion debe describir que es compatible con la version XL” Contract: README, the site (index/docs), DESIGN.md, packaging descriptions and the udev rule/installer text state support for both models; because no XL+ was available, the docs say it is implemented from Elgato's HID documentation and validated with a simulator, with hardware validation pending (do not claim hardware testing).
S5. Per-model data (human choice 'Separados por modelo'): the Stream Deck + keeps the existing data directory byte for byte; the XL+ uses <data>/sdeck-plus/devices/plus-xl/ as a complete independent configuration folder (layers.conf, organization.json, touchscreen.json, artwork.conf, info.json, obs.json, assets, links, button-errors.log, journals). Shared across models only: tray.json, updates.json and a new strict last-used-model preference, all in the config directory. Switching model (device change or 'Preview as') swaps stores and rebuilds the session without restarting the app; 'Preview as' is disabled while a device is connected; bundles record their model (format v5, older bundles are +) and import refuses a mismatched model with a clear message; importing into the + root must preserve devices/.

## Device model (parent design)
DeviceModel { id: 'plus'|'plus-xl', name, pid, key_cols, key_rows, dials, zones, key_px (square), key_rotation (None|Ccw90), key_flip_y, strip_px (w,h), zone_px (w,h), strip_rotation, partial_window_axis_swap, input_report_len, image_report_len, key_header_len, zone_header_len }. PLUS = 4x2 keys, 4 dials, 4 zones, key 120, strip 800x100, zone 200x100, no rotation. PLUS_XL = 9x4 keys, 6 dials, 6 zones, key 112 (Elgato docs; the Rust crate says 120), keys and strip rotated 90 degrees counterclockwise before JPEG, strip 1200x100, zone 200x100, partial_window_axis_swap=false (Elgato says logical coordinates; a python PR disagrees), key_flip_y=false. Open disagreements are per-model fields so they can be corrected on real hardware without redesign.

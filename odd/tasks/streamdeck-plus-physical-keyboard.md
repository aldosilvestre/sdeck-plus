# Stream Deck Plus physical keyboard input

## Authorized objective
User explicitly requires configured shortcuts to behave like physical keys, not Hyprland shortcut dispatch. CTRL + D holds Control during D press/release; SUPER + RETURN holds Windows/Meta during Enter press/release. Replace keyboard actions' hyprctl path with Linux uinput events. Preserve application direct argv, intentional command shell semantics, layer/artwork/UI work and persisted action wire formats.

## Decisions and constraints
- Linux virtual keyboard via uinput, not compositor dispatch or text typing; active keyboard layout determines symbols from physical evdev positions. Do not promise indistinguishable hardware or verified compositor acceptance.
- Existing cached libc 0.2.189 may be added as Linux-targeted direct dependency, offline only; no network/install/download.
- One lazy, persistent keyboard owner in serial action worker. Do not open/create real uinput or send real keys during tests; use mocks.
- No host permission/module/desktop changes, elevation, commits, staging, push or PR without explicit authorization. Effective uinput access remains unproven.
- Shared chord normalization accepts user examples, aliases/case/whitespace, merges checkbox modifiers deterministically with text (deduplicate), rejects ambiguous multiple main keys/modifier-only/malformed chords. Unsupported legacy key names remain structurally loadable and produce actionable execution error; no destructive migration.
- Backend must synchronize modifier down, key down/up, reverse modifier release; attempt release on failures, invalidate broken device. Creation/hotplug readiness must be bounded and errors clear.
- Engram tools unavailable; mirror unavailable. Forecast roughly 600–900 authored lines including Linux ABI safety/tests/integration. Delivery ask-on-risk, no delivery requested; size strategy deferred until authorized commits/PR. Protect coherent units; 400-line heuristic is advisory.

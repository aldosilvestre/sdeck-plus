# Virtual Stream Deck Classic in a web page

Large feature on branch feat/virtual-classic (from main @ 38e82ea). A header-menu flag starts a virtual Stream Deck Classic served over HTTPS on the LAN; phones and browsers log in with an app-defined password and use it like the real device, while the app lists and can disconnect the viewers.

## Specs
S1. "Podemos hacer un dispositivo virtual que puede ser activado mediante flag de un item en el menu, cuando este flag se active se virtualizara una version del stream deck classic, esto lo hara mediante una pagina web donde se mostrara como si fuera una dispositivo real." Human choices: the flag is an item of the header configuration menu ("Menú de configuración del header"); turning it on does NOT open a browser window (L27 overrides L2 "Abrir el navegador solo"); the page opens only from the menu's Open button or the QR code. Contract: the virtual Classic (15 keys, 5x3, keypad background) runs through the real hub, protocol, actions and two-second hold like a plugged-in Classic; it is listed in the Current selector while on; turning the flag off stops the server and removes the device. The flag starts off on every launch.
S2. Human choice "Una raíz propia (devices/virtual-classic/)": the virtual Classic has its own data root and configuration, independent of a real Classic, and can run alongside one.
S3. "esto tambien debe ser posible hacerlo desde un celular, es decir, debe tener diseño tambien mobile, es decir que se tiene que adaptar al tamaño de la pantalla en modo landscape." Contract: the page fits the device to the screen in landscape on phones (no zoom, no page scroll, safe areas, multi-touch, long press does not open a context menu), and works with mouse on desktop browsers.
S4. "en tanto el token, sera un password que sera definido en el servidor para que ingrese, es decir que desde el app se asignara un password, y este password se debera escribir cuando quieran ver la pagina del deck virtual. Si el password es correcto, se visualizan en la app los dispositivos que estan visualizando el deck virtual." Human choice "Ver y desconectar": the app lists each viewer (address, browser, connected since) with a Disconnect button; changing the password disconnects every viewer. The flag cannot start the server without a password. Superseded by L40 ("Password por sesión, no se guarda"): the password is set when the deck is turned on in a session, kept only in memory (verifier) while the app runs, reused if the deck is turned off and on again in the same session, and never written to disk; failed logins are rate limited.
S5. Transport, human choice "Red local (LAN)"; first "ok, vamos por esa" (HTTPS self-signed), then replaced by L31-L32: "necesito que el aviso no figure para ninguno, ya que el navegador puede terminar bloqueando los sitios riesgosos." and the choice "HTTP sin cifrado". Contract: the server listens on the LAN over plain HTTP/WebSocket (ws://), no certificate, no TLS, no fingerprint, so no browser certificate warning appears on any device. The password never travels in clear: login is a challenge-response (SCRAM-SHA-256 style: server nonce, PBKDF2 salted password computed in the page with bundled JS because crypto.subtle is unavailable on plain HTTP, client proof, server proof); the store keeps only salt, iterations and the derived verifier keys, never the password. Accepted trade-offs: traffic (key pictures, presses, session cookie) is readable on the LAN; no Wake Lock. Human choice "8765 fijo, editable en la app": default port 8765, editable and remembered.
S6. Human choices "QR con la URL" and "Diseño previo en el canvas": the app shows a QR code of the page URL (never the password); the page and app panel are designed as artboards in design/ before implementation.

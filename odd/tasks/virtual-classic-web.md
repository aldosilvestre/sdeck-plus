# Virtual Stream Deck Classic in a web page

Large feature on branch feat/virtual-classic (from main @ 38e82ea). A header-menu flag starts a virtual Stream Deck Classic served over HTTPS on the LAN; phones and browsers log in with an app-defined password and use it like the real device, while the app lists and can disconnect the viewers.

## Specs
S1. "Podemos hacer un dispositivo virtual que puede ser activado mediante flag de un item en el menu, cuando este flag se active se virtualizara una version del stream deck classic, esto lo hara mediante una pagina web donde se mostrara como si fuera una dispositivo real." Human choices: the flag is an item of the header configuration menu ("Menú de configuración del header"); turning it on opens the browser ("Abrir el navegador solo"). Contract: the virtual Classic (15 keys, 5x3, keypad background) runs through the real hub, protocol, actions and two-second hold like a plugged-in Classic; it is listed in the Current selector while on; turning the flag off stops the server and removes the device. The flag starts off on every launch.
S2. Human choice "Una raíz propia (devices/virtual-classic/)": the virtual Classic has its own data root and configuration, independent of a real Classic, and can run alongside one.
S3. "esto tambien debe ser posible hacerlo desde un celular, es decir, debe tener diseño tambien mobile, es decir que se tiene que adaptar al tamaño de la pantalla en modo landscape." Contract: the page fits the device to the screen in landscape on phones (no zoom, no page scroll, safe areas, multi-touch, long press does not open a context menu), and works with mouse on desktop browsers.
S4. "en tanto el token, sera un password que sera definido en el servidor para que ingrese, es decir que desde el app se asignara un password, y este password se debera escribir cuando quieran ver la pagina del deck virtual. Si el password es correcto, se visualizan en la app los dispositivos que estan visualizando el deck virtual." Human choice "Ver y desconectar": the app lists each viewer (address, browser, connected since) with a Disconnect button; changing the password disconnects every viewer. The flag cannot start the server without a password. The password is stored only as a hash; failed logins are rate limited.
S5. Transport, human choice "Red local (LAN)" then "ok, vamos por esa" (HTTPS with a self-signed certificate, no MAC binding): the server listens on the LAN over HTTPS/WSS with a locally generated certificate (private key 0600 in the config dir); the app shows the certificate's SHA-256 fingerprint. Human choice "8765 fijo, editable en la app": default port 8765, editable and remembered.
S6. Human choices "QR con la URL" and "Diseño previo en el canvas": the app shows a QR code of the page URL (never the password); the page and app panel are designed as artboards in design/ before implementation.

- W2 (T4), new lib module `sdeck_plus::virtual_deck` (src/virtual_deck.rs + src/virtual_deck/): `ServerConfig { port: u16, bind: IpAddr (default 0.0.0.0), config_dir: PathBuf }`; `hash_password(&str) -> Result<String,String>` (Argon2id PHC string; rejects < 8 chars with "At least 8 characters."); `VirtualDeckServer::start(config, password_hash: String, inputs: Sender<DeckInput>, snapshot: Box<dyn Fn() -> Vec<DeckFrame> + Send + Sync>) -> Result<VirtualDeckServer,String>`; `publish(&self, DeckFrame)` to every viewer; `viewers() -> Vec<Viewer { id: u64, address: IpAddr, browser: String /*e.g. "Android · Chrome 131"*/, since: SystemTime }>`; `disconnect(id)`; `set_password(hash)` (disconnects all with reason password-changed); `events() -> Receiver<ServerEvent::{ViewersChanged, Error(String)}>`; `url_candidates() -> Vec<String>` (https://<lan-ip>:<port>/); `fingerprint() -> String` ("SHA-256 AA:BB:..."); `stop(self)` joins every thread. `DeckInput { key: u8, pressed: bool }`, `DeckFrame::{Key{key,jpeg}, Background{jpeg}, Brightness(u8), Reset}`. Certificate: rcgen ECDSA P-256 self-signed, SAN = every LAN IPv4 + localhost, stored config_dir/virtual/cert.pem + key.pem (0600, dir 0700), regenerated when the SAN set changes. TLS: rustls with ring provider. Login: GET / without session -> login page; POST /login (form `password`) -> 303 + cookie `sdeck_session` (32 random bytes hex, HttpOnly; Secure; SameSite=Strict; Path=/) or 401 JSON {"error":"Wrong password.","tries_left":n}; after 5 failures per IP -> 429 {"error":"Too many tries.","retry_after":30}. GET /ws requires the cookie and Origin == https://<Host>; else 403. Max 8 viewers. Static page bytes come from `include_str!("virtual_deck/page/index.html")` and `login.html` (owned by W3).

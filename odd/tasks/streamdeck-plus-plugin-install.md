# Add a plugin from the app (local folder or HTTPS repository)
Objective: Let the user add a plugin from the app by giving a folder path or an HTTPS repository address, verifying that it follows the sdeck-plus plugin format before anything is installed.
Branch: feat/plugin-install (stacked on feat/plugin-sdk @ 1b2f435); delivery: feature-branch-chain (cached user choice "1"), local only; checks: cargo test --offline (headless, --no-fail-fast), fmt, clippy -D warnings, plugin projects' unittest.

## Specs
S1. "podemos agregar en la app la posibilidad de agregar un plugin, ya sea indicando el path donde esta el plugin o bien escribiendo la direccion del repositorio?" Checks: the app has an "Add plugin" entry point that accepts either a folder path or a repository address; the installed plugin then appears as its own sidebar item like any other.
S2. "Cabe resaltar que debemos verificar que el plugin cumpla con el formato de plugins para sdeck-plus" Checks: before installing, the candidate is validated with the same rules as the plugin validator (manifest, executable confinement, limits, no symlinks); nothing is installed when validation fails; the problems are shown readably.
S3. Decision on repositories (user choice, quoted): "Solo direcciones HTTPS con el git del sistema (recomendado)". Checks: only `https://` addresses are accepted; fetched with the system `git` as a shallow clone without submodules or hooks, no credential prompts, user git configuration neutralized; the downloaded commit is shown; no SSH, no other schemes.

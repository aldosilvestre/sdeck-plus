# Plugin UI polish, separate plugin projects and plugin SDK docs
Objective: Move the plugin rescan control into the binding toolbar with a plugin separator, move the demo plugins to separate projects that declare their dependencies, and document a plugin SDK in sdeck-plus.
Branch: feat/plugin-sdk (stacked on feat/external-plugins @ f665b39); delivery: feature-branch-chain (cached user choice "1" from the previous plugin feature), local only; checks: cargo test --offline (headless), fmt, clippy -D warnings, python unittest in each plugin project.

## Specs
S1. "el boton de reescaneo de los plugins podria esta a la altura de los botones de save, test y delete. Pero ubicado a la derecha de la seccion, separados de estos y con solo el icono, y cuando se haga un hover deberia mostrar la leyenda de actualizar plugins." Checks: the rescan control sits in the same row/height as the save, test and delete buttons, right-aligned and visibly separated from them; icon only; hover tooltip says it updates the plugins (UI copy is English, so "Update plugins"); keyboard focus and an accessible name still work; behaviour (rescan, no plugin execution) unchanged.
S2. "En tanto a la seccion de plugins, podrias poner un separador que denote cuales son los plugins." Checks: a separator/heading marks where the plugin entries of the sidebar begin, so plugins are distinguishable from the built-in actions; separate items per plugin are kept.
S3. "los plugins no necesariamente deben estar en la carpeta extension, estos deben estar como proyectos separados (cada plugin nuevo, un nuevo repositorio)." Checks: the Discord and MeRGBW plugins live as separate projects, each its own local Git repository outside sdeck-plus, and extensions/ no longer exists in sdeck-plus. Approved locations (user choice "Crearlos ahí y quitar extensions/ de sdeck-plus"): /home/aldo/Documents/git/sdeck-plugin-discord and /home/aldo/Documents/git/sdeck-plugin-mergbw. No remote repository is created and nothing is published.
S4. "En estos proyectos se debe especificar que dependencias son necesarias para que el plugin funcione en la aplicacion." Checks: each plugin project states its required dependencies (README and machine-readable declaration); assumption (not a user requirement): an optional `requirements` list in manifest.json that the app shows in the plugin's sidebar item and checks only by looking up commands on PATH, never installing or running anything.
S5. "Tambien en el proyecto principal sdeck-plus debemos dejar en la documentacion lo necesario para que puedan integrar un nuevo plugin a sdeck a modo de sdk." Checks: sdeck-plus documents everything an author needs (layout, manifest reference, protocol, limits, environment, dependencies declaration, security model, installation, testing, packaging as a separate repository, compatibility), with a validator tool to check a plugin project; docs site page linked from the docs and sitemap.

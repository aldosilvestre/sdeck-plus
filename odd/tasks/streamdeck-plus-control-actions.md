# Stream Deck Plus control actions and layers

## Objective
Provide control-specific action configuration, independent layers with a button-selectable move-to-layer action, and command, key, application, and shortcut actions.

## Scope and decisions
- Target desktop: Hyprland / Omarchy (user confirmed).
- Key action means one complete key press and release; shortcut means a simultaneous modifier/key combination.
- Commands explicitly use `/bin/sh -c`; application launches remain executable plus argv with no implicit shell.
- Encoder direction bindings match any nonzero tick magnitude. Preserve legacy exact-tick bindings.
- Touch flick coordinates provide directional swipes; preserve generic legacy touch bindings.
- Preserve existing layers, Base protection, persistence, and all pre-existing uncommitted work.
- Replace raw binding entry as the primary interface with control/event/action selectors and relevant parameter fields.
- Do not modify desktop configuration, install packages, inject real keys in tests, push, or create PRs.
- Commits require explicit user request; work-unit commit identities pending that authorization.

All controls support appropriate actions; buttons can select another independently configured layer. Command, key, application, shortcut, and move-to-layer actions persist and dispatch correctly. Invalid configuration and failed backend execution surface actionable errors, not silent success. Legacy bindings continue to load and work.

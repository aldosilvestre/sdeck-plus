Your Stream Deck +, native on Linux.

sdeck-plus is a GTK4 control desk for the Elgato Stream Deck + (Stream Deck Plus). Configure its eight keys, four dials and touch strip, organize profiles, pages and folders, show live information, route audio, style button text and drive OBS Studio.

Install View on GitHub

This project is still under construction. Developed and tested on Arch Linux with Hyprland.

Every control

8 keys, 4 dials with press and rotation, and touch-strip tap, hold, flick and swipes.

Profiles

Profile tabs with pages and folders, switched automatically by the focused application.

Artwork, text and icons

Images for keys, the strip and touch zones, styled text on each key, and an action icon on keys and zones without artwork.

Runs in the tray

Bindings stay active with the window closed, with optional start at login.

Features

Current native GTK widgets with demonstration profiles and artwork. Input feedback and readings are deterministic examples; no device, audio-output or OBS actions are performed for these captures.

Configure any control

Untouched controls start with None. Click a key, dial or the touch strip on the hardware preview, choose an event and an action, then save. Saving never runs the action; Test action runs it on demand.

  • Move to a profile or page, run a command, open an application
  • Keyboard shortcuts through a virtual keyboard
  • Play sounds and the categorized More actions

None stays inert

New buttons, profiles and pages start without an action. None can still display artwork, button text or live information, but it never runs an action or starts a page-return timer.

Dials and touch strip

Each dial has independent Press, Clockwise and Counterclockwise bindings, perfect for volume or brightness. The touch strip binds tap, hold, flick and directional swipes.

Touchscreen settings, images and dial press/turn assignments follow the profile's selected touch page, independently of keypad pages and folders. Existing touch pages receive their profile's main-page dials on upgrade, without replacing touch edits or discarding legacy records. Select the strip to add, choose or delete a Touch page. Swiping left shows the next touch page and swiping right the previous one by default; assign any action to a swipe to override it. Left/right edge indicators show available previous/next touch pages, including over section images and live information; unavailable directions are hidden. Existing configurations and swipe assignments are preserved. The app always starts on the Base profile's first page.

More actions

Extended actions are grouped into System, Multimedia, Organization, Device and OBS. Each action shows only its own fields and a short description of what it does.

Choose or rotate audio outputs

More actions > Multimedia > Change audio output can select a fixed PipeWire output or Rotate through connected outputs on each press. Saved fixed targets use stable names, not temporary numeric IDs. Choosing or saving never changes audio.

Live information

Show volume, output device, brightness, time and date, weather, CPU, memory, temperature or OBS state. Readings update on keys and eligible dial or touch-section bindings, over their own artwork. None can show information without running an action.

Weather accepts a city or coordinates and needs an internet connection. The readings below are demonstration values.

Button text

Draw text on any key with an installed font, a size from 6 to 120 px, horizontal or vertical orientation and a position on a 3x3 grid, with tooltips and keyboard focus. The popup names the key and page being edited, and its preview shows the key exactly as the device will.

Artwork and touch zones

Assign PNG, GIF or any image supported by GdkPixbuf to thirteen targets: eight keys, the touch-strip background and four touch zones. Images are copied into the app's data directory and replayed on reconnect.

Profiles, pages and folders

Each profile is a tab with its own pages, folders, bindings and artwork. Associate a profile with a window class or executable and it is selected automatically when that application gets focus (Hyprland IPC).

Return to a page

Enable a delayed return on a non-None binding, choose the exact page and set a delay from 1 to 86400 seconds. Activating that binding again restarts the wait. Saving a binding never starts the timer.

Save and restore configuration

The top-right Menu imports and exports .sdeck-plus.json files containing saved profiles, pages, bindings, button text, local sounds, information and OBS settings.

Version 2 exports image filenames only, without base64 image data. The named files must already exist in the destination's assets directory. Import validates first, asks for confirmation and keeps the previous configuration as a backup. Older version-1 exports remain supported.

Exports include saved OBS credentials. Keep them private. Cancel or an invalid file leaves the current configuration intact.

Light and dark GTK themes

The native controls follow the desktop theme while keeping consistent spacing, a violet primary action and a distinct cyan keyboard-focus outline.

OBS Studio

Connect to OBS's built-in WebSocket server on a local endpoint. Switch scenes, toggle recording or streaming, mute inputs and show or hide sources. The connection test only queries state; it never starts an output.

Built-in help

Choose Menu > Help for the three-step guide: select a control, configure an action, then save or test it.

Configuration

How each part of the application behaves, where it stores its data and what it needs from the system. Saving or inspecting a binding never executes it; only Test action or input from the device does. The app never installs packages, changes permissions or edits OBS configuration.

Getting around

Main window and connection status

The header says in plain words whether the Stream Deck + is connected (for example "Stream Deck + not connected — plug it in") next to a colored Not connected, Unavailable, Disconnected or Connected badge; hover it for the USB IDs (VID 0x0FD9, PID 0x0084) and technical details.

If the device is absent, inaccessible or disconnected, the window stays open, reports the state and retries detection. Touch gestures use Elgato's 800 × 100 logical-pixel space and are reported after the interaction completes, not as separate contact start and release events. Each dial in the preview shows the action it is assigned to.

Configure an action

  1. Select a profile tab and page, then click one of the eight keys, the touch strip or one of the four dials.
  2. Pick an event valid for that control: key press; dial press, clockwise or counterclockwise; touch tap, hold, flick and directional swipes.
  3. Pick an action and fill only its visible fields. Shortcuts accept a full chord such as CTRL + D or one key with the optional Ctrl, Alt, Shift and Super toggles.
  4. Save binding creates or updates the control event; Remove binding clears it.

A toast confirms success only after the binding is written to disk and disappears after five seconds; errors stay until dismissed or replaced. Selecting a configured event loads its saved action for editing. Bindings do not inherit or fall through between layers.

Assignment summaries

Hover a control to see its assignments on the selected keypad page or touchscreen page, including Unassigned events: dials list Press, CW and CCW; the strip lists tap, hold, flick and directional swipes. Legacy exact-tick rotation overrides appear separately. Long text is shortened; select the event to see every saved field. Summaries refresh after saving or removing bindings, changing layers and Go to profile or page actions.

Selection, live input and swapping keys

The control being edited has a thick violet ring. A pressed key or dial gets a green outline and brightens while held, a dial turn flashes amber, and a touch tap, hold or flick lights the touched zone in cyan, drawn over any artwork.

Drag a key onto another key in the preview to exchange their action, background image and text styling on the current page. An empty key exchanges its empty configuration too. The exchange is saved automatically and never runs either action; other pages, dials, touch zones and unsaved editor drafts are unchanged. Dropping on the same key or cancelling changes nothing.

Controls and actions

Action types

The Action menu offers layer and page switching, shell commands, launching applications, keyboard shortcuts, named events, the categorized More actions, Play sound and None. Untouched buttons, including those on new profiles and pages, start with None: it keeps a saved binding that does nothing, can still show artwork, text or live information, and never schedules a page return.

Test action runs the selected action immediately and can affect the desktop, the device or OBS; test only what you intend to perform.

Dials and device brightness

The four dials have independent press, clockwise and counterclockwise bindings, for example volume up and down on rotation and mute on press, or relative brightness on another dial. Mouse-wheel directions are vertical or horizontal.

Device brightness is the Stream Deck's display, not the monitor backlight. Sleep sets brightness to zero and wake restores the remembered level; before an explicit absolute level, relative and wake actions assume 100% because the device cannot report its brightness. Legacy exact-tick rotation bindings remain supported and take priority over directional ones.

Sounds and audio output

Choose Play sound, then Choose file... or enter a path. WAV, MP3, FLAC, OGG, M4A/AAC, Opus and other formats decoded by mpv work. Playback replaces the app's previous sound; More actions > Multimedia > Stop audio file stops only app-owned playback, not other media players.

Change audio output switches the default PipeWire output with wpctl; Refresh discovers new outputs with pw-dump. Bindings store the stable device name, so reconnecting does not select a different device; a disconnected saved device reports an error when used. Rotate advances from the system's current output to the next connected one on each press, wrapping after the last. Volume uses the default output in 5% steps, capped at 100%. Media transport uses the session's MPRIS player.

Text, files, websites and processes

Pasting text uses the Wayland clipboard (wl-copy) and a physical Ctrl+V chord, not synthetic Unicode keycodes: it replaces the clipboard and needs the focused application to accept Ctrl+V. Files, folders and HTTP(S) websites open with xdg-open. Closing an application targets its exact Linux process basename (1–15 ASCII bytes), not a window title or a shell pattern.

Commands and application launch

Applications are launched with distinct process arguments; no shell evaluates them. In the argument box, an empty box means zero arguments and \empty on its own line means one empty argument. Backslash, newline, carriage return and tab are written as \\, \n, \r and \t, so leading and trailing spaces are preserved.

Only the Command action runs /bin/sh -c with the configured string. External actions run one at a time on a background worker, and failures appear in the window without blocking it.

Return to a page afterwards

A non-None binding can return to a page after a delay: tick Return to a page afterwards, pick the destination (listed with its profile and folder, such as Base or Studio / Page 2) and a delay of 1–86400 seconds. Pressing the key again restarts the wait and Device > Cancel timer cancels it. Saving never starts the wait.

Physical keyboard actions and /dev/uinput

Shortcut uses a Linux uinput virtual keyboard, not compositor dispatch, shell commands or text typing. Without modifiers it sends one key down/up; with modifiers it holds them around the main key and releases them in reverse order (CTRL + D, SUPER + RETURN). Modifiers are never kept held between actions; failed sends attempt release cleanup. Key names and aliases opens a reference of every accepted name, without saving or running the draft.

  • Chord text and modifier toggles are merged in CTRL, SHIFT, ALT, SUPER order. Names are case-insensitive; Control = CTRL, Win/Windows/Meta = SUPER, Return = Enter. Uppercase letters do not add Shift.
  • Supported keys: ASCII letters and digits, F1–F24, Enter, Tab, Escape, Space, navigation, named punctuation, keypad and media keys. Unknown names, empty segments, several main keys or modifier-only chords are rejected.
  • Media names: XF86AudioLowerVolume, XF86AudioRaiseVolume, XF86AudioMute, XF86AudioMicMute (mute_mic), XF86AudioPlay (play), XF86AudioPause (media_pause), play_pause, XF86AudioNext (next_track), XF86AudioPrev (previous), XF86AudioStop, XF86AudioRecord, XF86AudioRewind, XF86AudioForward, XF86Eject, XF86MonBrightnessUp/Down and XF86KbdBrightnessUp/Down/XF86KbdLightOnOff. PAUSE, NEXT and STOP keep their keyboard meanings; desktop bindings decide what media keys do.
  • Names identify physical key positions; the active keyboard layout decides the resulting symbols.
  • Saved legacy Press key actions keep working and show as a Shortcut without modifiers; they are rewritten only when you save them again. Unsupported legacy names stay visible and report an error when run.
  • One persistent virtual keyboard is opened on first use, after a 200 ms discovery grace period. It needs kernel uinput support and effective access to /dev/uinput; failures are reported with no fallback, privilege escalation, module loading or permission change. Ask an administrator for narrowly scoped access if needed. Mouse-wheel actions need the same access.

Live information on keys and dials

Under the action of a key or dial, tick Show live information and choose volume (crossed out while muted), audio output device, Stream Deck brightness, time and date, weather, CPU, memory, temperature (bars turn amber and red under load) or OBS state (recording, streaming and scene). On a key the icon, value, bar and caption are drawn over the key's own image and always fit; on a touch section they sit on a see-through tile beside the icon, leaving the page-indicator edge free. Only the control showing a value is redrawn, the binding's action still runs, and the window preview matches the device.

Each touch section can show information for its Tap or Hold binding. A dial's section shows its press binding first, then its turns, then a tap or hold on that section. Flick, swipes and whole-strip gestures cannot show information. Weather uses Open-Meteo through curl with a city or latitude,longitude, needs internet access and shows -- when the lookup fails. Volume and audio device use wpctl.

Touch strip and touchscreen pages

Sections and gestures

The strip has four sections, one above each dial. Choose Touch, then control 1 to 4, and give each section its own Tap and Hold binding. Any keeps the older whole-strip bindings, which still handle taps no section claims. Flick and swipes always apply to the whole strip.

Touch bindings, section information, strip and section images and every dial binding belong to the profile's selected touchscreen page, not to keypad pages or folders: changing a keypad page or opening a folder keeps the touch page.

Touchscreen pages and swipes

Select a dial, the strip or a section to show Touch page. Browse with its selector and arrows, add a blank page with +, or delete the selected one with the trash button after confirming (keypad pages are unchanged; a profile keeps at least one). Each profile remembers its selection across restarts and holds up to 64 touch pages.

Swiping left shows the next touch page and right the previous one while those gestures have no binding of their own; a Flick binding also takes precedence. Swipe up and down have no default. More actions > Organization > Next/Previous touchscreen page is offered only for touch controls and does not wrap. Edge chevrons on the device and preview show available directions. Delayed returns still target keypad pages.

Touchscreen data and upgrades

Existing configurations migrate automatically: each distinct touch and dial configuration in a profile becomes a touchscreen page, equal ones share a page, and actions, None bindings, delayed returns, information and image references are preserved. Upgraded version-1 touch pages keep their edits and receive a copy of the dials from their profile's main keypad page; legacy records are retained and migration is not repeated. The upgraded touchscreen.json is version 2, which older app versions cannot read.

Invalid touchscreen configuration blocks saving instead of replacing the file. layers.conf and touchscreen.json are staged together; if the final replacement fails the previous layer file is restored, and a synced recovery journal lets startup restore or keep the pair after an interrupted save. Unreadable recovery state is reported, never silently replaced.

Profiles, pages and folders

Profiles and application switching

Profiles are tabs, with Base always available and undeletable. Organize > New profile creates one (Create profile stays disabled until the name is new). Organize > Edit profile sets an optional window class or executable name such as kitty, firefox or obs; Save changes is enabled only when the rule changed. Base cannot require an application.

Detection uses Hyprland IPC focus events, not process polling. A matching application selects its profile; unmatched or unavailable focus returns to Base; focusing the configuration window keeps the last external context. A manual tab choice lasts until the next external focus change. Selecting a profile never launches its application. Every start opens on Base's first page.

Pages

New page asks for a name first. The pencil renames the current page (Save name or Enter): names must be non-blank, without control characters and at most 64 UTF-8 bytes; surrounding spaces are trimmed. The trash button deletes the page with its folders, bindings and artwork after confirming. Previous, next and parent arrows sit before the page name. Navigation stays within the current profile and folder, and switching tabs restores that profile's last page for the session.

Page folders

The folder icon in the page bar opens Page folders. Type a name in New folder name and press Enter; blank, duplicate and invalid names are explained while typing. Each row offers Open, Link to control (saves navigation to the folder on the selected control and event without opening it), Rename (Enter saves, Escape cancels; linked controls follow the new name) and Delete (removes only this page's folder and its links). Parent returns to the exact owning page.

organization.json stores this hierarchy (version 2, with stable page-owner keys). Version-1 folders attach to their former parent's first surviving page; flat layers load as independent profiles; legacy brightness-v1 and scroll-v1 records load as typed actions. Invalid metadata is kept untouched and disables organization writes until repaired.

Appearance

Button text

Select a key and click Add text (Edit text once saved). The popup names the key and page, for example "Key 3 on “Everyday / Page 1”". Choose an installed font, a size from 6 to 120 px, horizontal or vertical orientation (vertical rotates the text 90° clockwise) and a position on a 3x3 grid. Text is white with a black outline and may span several lines.

The preview shows the key as the device will: over its image, over its action icon when the text leaves room, or over black, with a warning when the text does not fit (the device clips it). Save text or Ctrl+Enter saves; it is enabled only for non-blank changes, flagged by "Unsaved changes". Closing discards the draft. Remove text keeps the background image, and clearing the image keeps the text.

Window layout and themes

The window opens at 1000 × 700 with the device preview on the left and the editor on the right; long forms and smaller windows scroll vertically. The desk uses the window width up to 1240 px and centers beyond it; the preview grows up to 1.5 times, and at 640 px the preview and editor stack without horizontal scrolling. Charcoal (dark) or pale-gray (light) surfaces follow the desktop GTK theme, with violet save actions and a cyan keyboard-focus outline. Transitions follow GTK's animation setting. The full layout contract is in DESIGN.md.

Background images

Pick a target in Artwork target (active layer), then Image… or × (Clear artwork). There are thirteen targets: eight keys, the touch-strip background and four touch zones. Clicking a key or zone selects its target; clicking a dial selects only its binding. PNG, GIF and any format supported by the installed GdkPixbuf loaders work; GIFs are sent as a still image because the hardware upload format is JPEG. Images are center-cropped and sent as 120 × 120 (keys), 800 × 100 (strip) or 200 × 100 (zone) JPEGs; the strip background and zones are layered.

Images are copied into the data directory, so originals can be moved or deleted. Artwork is independent per layer: switching layers replaces the device's whole image state (unassigned keys turn black) and the same state is replayed after reconnecting. Clearing a key sends a black image; clearing strip artwork rebuilds the strip from what remains. A file chooser saves to the target and layer captured when it opened. A failed import keeps the current assignment, storage failures disable artwork writes instead of saving an empty fallback, and upload failures appear in the connection status.

Binding icons

Every action has a two-tone icon used in the Action and More actions menus, on the preview dials, and on keys and touch sections without their own artwork, both in the preview and on the device. Each family has its own color: media violet, audio cyan, OBS red, apps and system amber, websites blue, pages and folders white. Badges above the preview strip list what swipes, tap and hold do (dimmed while an unbound swipe keeps its default page change). Your artwork always wins, button text keeps its placement (the icon uses free space above or below it), and keys set to None or left unassigned stay black. Icons are never saved into your artwork or text.

OBS Studio

Connect to OBS

In OBS, enable the built-in WebSocket server under Tools > WebSocket Server Settings. In sdeck-plus, click OBS in the profile bar, enter the local endpoint (normally ws://127.0.0.1:4455) and password, save and test. The test queries scenes and recording/streaming state and never starts an output. Scene, source and input names must match OBS.

Only loopback endpoints are accepted. Requests run on a worker with bounded waits, and authentication, connection and request errors appear in the window. Credentials are stored in owner-only obs.json, not in bindings, and are masked in the editor and diagnostics. The app does not enable the OBS server or change its configuration.

Data, tray and lifecycle

Data location and files

Configuration lives in $XDG_DATA_HOME/sdeck-plus, or $HOME/.local/share/sdeck-plus when it is unset (normally ~/.local/share/sdeck-plus): layers.conf (keypad layers and bindings), touchscreen.json, organization.json, info.json, obs.json, the assets directory with its artwork manifest, and button-errors.log.

An unreadable or unsupported layers.conf leaves configuration unavailable with writes disabled; repair it and restart. In a readable file, invalid, conflicting or duplicate records are removed and logged with their reasons in button-errors.log. Removing a layer also removes references to it.

Backup and restore

Menu > Export configuration... writes one owner-only .sdeck-plus.json with profiles, folders, pages, bindings, artwork filenames, button text, live information, page returns, local sound files and OBS settings, including credentials. Format version 2 stores images as {"path":"assets/filename.png"} without image data. Executables, commands, document paths, autostart and tray preferences stay local references.

Before importing, the named images must exist in the destination's assets directory; missing or invalid images cancel the import. Import validates the file, asks for confirmation, keeps the previous configuration in a sibling backup directory whose path it shows, and refreshes the device. It never runs a saved action. Older exports with embedded images are still accepted.

System tray and login startup

Closing the window hides it; the device, bindings, artwork, timers and app-owned playback stay active until Quit. Either click on the tray icon opens Open configuration, Start at login, Start in tray (on by default; saved in tray.json), About and Quit. A tray supporting StatusNotifierItem is required.

Autostart writes $XDG_CONFIG_HOME/autostart/sdeck-plus.desktop (or ~/.config/autostart/) and starts the current executable with --background; disable and re-enable it after moving the executable. Run cargo run -- --background for a quiet manual start. Repeated launches reuse the running instance. If the session bus is unreachable, closing the window exits instead of hiding.

Quitting and reconnecting

Quit discards pending uploads, turns off display brightness, clears the keys and touch strip to black, stops the action worker and app-owned playback, cancels timers and releases the device; a blocked driver call can delay exiting. Independently opened applications stay open. On the next launch brightness returns to 100% and saved artwork is replayed. While running, unplugging and reconnecting retries automatically.

Upgrading from the previous name

The application, package and executable are named sdeck-plus, with the data directory sdeck-plus and autostart entry sdeck-plus.desktop; the application ID stays the same so launches reuse one instance. Files are not migrated automatically: quit the old application, move its data directory to the new path to keep profiles, artwork and OBS settings, then disable the old autostart entry and re-enable Start at login.

Install

Builds from source with Cargo and installs for the current user only. It never installs system packages or changes device permissions.

Build and install

sudo pacman -S gtk4 base-devel
git clone https://github.com/aldosilvestre/sdeck-plus.git
cd sdeck-plus
./install.sh

Or run it directly from the checkout:

cargo run

The installer builds the release binary with Cargo.lock and installs ~/.local/bin/sdeck-plus, the launcher ~/.local/share/applications/dev.streamdeck.EventMonitor.desktop, the icon ~/.local/share/icons/hicolor/scalable/apps/sdeck-plus.svg and the license in ~/.local/share/doc/sdeck-plus/. PREFIX overrides the executable prefix, an absolute XDG_DATA_HOME the data directory, and CARGO_TARGET_DIR the build output. It runs from any directory, refuses to run as root, does not enable autostart or launch the app, and re-running it updates the files (./install.sh --help for usage).

Afterwards it reports a missing PATH entry, a running instance still using the old executable, a Start at login entry pointing elsewhere, missing optional tools, and a connected device your user cannot open (printing the udev rule an administrator can install, without running it).

Remove it with ./install.sh --uninstall, using the same PREFIX and XDG_DATA_HOME. Configuration, profiles, artwork and any Start at login entry are kept, and a running instance is not stopped.

Requirements

  • Rust stable toolchain and Cargo, a C toolchain, pkg-config and glib-compile-resources
  • GTK 4.8 or newer and libudev development files
  • A StatusNotifierItem tray (for example, Omarchy's)
  • Stream Deck + over USB, with permission to open its HID node
  • Optional, per action: xdg-utils (files and websites), wireplumber (wpctl), pipewire (pw-dump), curl (weather), wl-clipboard (text), procps-ng (closing processes), mpv (sounds), an MPRIS player (media transport)
  • Keyboard and mouse-wheel actions need /dev/uinput access

If opening the device is denied, use your distribution's supported mechanism, for example an administrator-installed udev rule scoped to this VID/PID with TAG+="uaccess", then reconnect the device. Missing tools or access are reported; the app never installs packages or changes permissions.

See Configuration for how each feature behaves.

Development

Checks and tools for working on sdeck-plus from a checkout. Build requirements are listed under Install.

Checks

cargo fmt --all -- --check
env -u DISPLAY -u WAYLAND_DISPLAY GDK_BACKEND=x11 cargo test --offline
cargo clippy --offline --all-targets --all-features -- -D warnings

The headless run covers the Rust suites but skips display-dependent GTK bodies. Run native GTK cases separately in a graphical session so each process owns its GTK main thread, for example:

GDK_BACKEND=x11 cargo test --offline --bin sdeck-plus \
  tests::button_text_alignment_icons_update_preview_and_save \
  -- --exact --nocapture --test-threads=1

The serialized layout test checks the thirteen artwork paths and every action at 1000 × 700, horizontal fit at 1840 × 980, 1280 × 720 and 960 × 640, and scroll reachability at 640 × 480. These checks do not replace real file-chooser, accessibility or device verification.

Documentation screenshots

The captures in docs/screenshots are generated from the production widgets with isolated demonstration profiles; they do not operate a device, change audio output or connect to OBS. Regenerate them from a graphical session (captures use a 1000 × 950 window):

GDK_BACKEND=x11 STREAMDECK_DOC_SCREENSHOTS_DIR="$PWD/docs/screenshots" \
  cargo test --offline --bin sdeck-plus \
  tests::documentation_screenshots::regenerate_documentation_screenshots_when_explicitly_requested \
  -- --exact --nocapture --test-threads=1

Opt-in real-device checks

Close other instances first so one HID worker owns the device. --device-controls sends real brightness (50%, relative), sleep and wake reports and leaves brightness at 50%; --input waits up to 60 seconds for a key press, dial rotation and touch gesture.

cargo run --offline --example verify_streamdeck -- --device-controls
cargo run --offline --example verify_streamdeck -- --input
cargo run --offline --example verify_obs -- "$HOME/.local/share/sdeck-plus"
cargo run --offline --example verify_desktop
dbus-run-session -- cargo run --offline --example verify_multimedia -- /path/to/silent.wav

The OBS check authenticates, queries scenes and output state and reselects the current scene, without recording or streaming; configure obs.json through the app first. The desktop check pastes exact Unicode into its own window; the multimedia check runs mpv on an isolated D-Bus session and needs a local silent audio file and the mpv-mpris plugin.

In-process event API

src/event_api.rs defines the typed MonitorEvent boundary: Connection(ConnectionState), Input(protocol::Event) for decoded HID input and ArtworkResult for upload results; consumers ignore the Heartbeat probe. start_hid_monitor returns an owned HidController with an artwork sender, explicit cancellation and idempotent joined cleanup, and runs initialization, retries, timed reads and serialized image writes on one thread. Only the newest pending artwork snapshot is applied, and GTK polls results with a short GLib timer. Internal events use the MonitorEvent::AppEvent channel. There is no TCP, HTTP or WebSocket listener.

The protocol decoder validates the report ID and declared little-endian payload length before decoding input.
